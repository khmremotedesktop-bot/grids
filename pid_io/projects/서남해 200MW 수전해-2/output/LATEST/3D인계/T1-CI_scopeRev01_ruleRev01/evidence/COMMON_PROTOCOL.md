> **읽기 전에** 이 프로토콜의 기준은 **엔지니어 관점(마스터)** 하나입니다. 컴퓨터 관점과 유지보수 관점은 마스터를 옮긴 **번역본**입니다. 둘이 다르면 항상 마스터가 맞고, 번역본은 고치지 않고 마스터를 고친 뒤 다시 번역합니다. 숫자 기준은 규칙의 기준값(params) 한 곳에만 있습니다. 자세한 관리 방법은 P00.

## 엔지니어 관점 (마스터)

### P00 이 프로토콜 읽는 법 · 고치는 법
- **대상** 이 공통 프로토콜 전체 (모든 규칙)
- **조건** 규칙을 만들거나 고치거나 인계받을 때
- **할 일**
  1. 기준은 엔지니어 관점(마스터) 하나다. 컴퓨터 관점과 유지보수 관점은 마스터의 번역본이다.
  2. 규칙을 바꾸려면 마스터(대상 · 조건 · 할 일 · 예외 · 판정 · 근거)와 기준값만 고친다. 번역본은 직접 고치지 않는다.
  3. 마스터가 바뀌면 번역본은 '다시 번역 필요'가 되고, 다시 번역해서 사람이 확인해야 '확정'이 된다.
  4. 번역하다 애매하면 짐작하지 않고 질문으로 남긴다. 엔지니어가 마스터를 고쳐서 답한다.
  5. 숫자 기준은 기준값 한 곳에만 둔다. 마스터와 번역본과 프로그램이 같은 값을 쓴다.
  6. 마스터 승인은 계장 공종 책임자가 하고, 승인자 · 일자를 남긴다. 고칠 때마다 버전을 올리고 변경 이력을 남긴다.
- **예외**
  - 프로젝트 한정 규칙(태그 번호 · 프로젝트 이름이 들어간 것)은 공통에 넣지 않는다
- **판정** 번역본이 마스터와 다르면 번역본을 따르지 않는다 (마스터 우선). 다시 번역 필요 · 질문 있음이 남아 있으면 점검 실패.
- **근거**
  - 사용자 결정 2026-11-27 (마스터 = 엔지니어 관점)
- **상태** DRAFT

### P01 같은 입력이면 같은 물량
- **대상** 모든 물량 결과 (인덱스 · 케이블 · JB · 트레이 · 서포트 · 3D 데이터)
- **조건** 같은 도면 · PLOT · 3D와 같은 체크리스트 값
- **할 일**
  1. 누가 언제 돌려도 같은 물량이 나와야 한다.
  2. 결과 숫자를 손으로 고치지 않는다.
  3. 바꾸려면 입력이나 사람 결정을 바꾸고 다시 계산한다.
- **판정** 같은 입력인데 물량이 다르면 HOLD (원인 확인).
- **근거**
  - pid_io 설계 원칙
- **상태** DRAFT

  2. 3D가 사람 결정을 덮지 않는다.
- **예외**

### P11 3D와 PLOT이 다를 때
- **대상** PLOT과 배관 3D 모델의 위치 · 높이 · 랙 · 구조물 차이
- **조건** 3D 모델을 올렸을 때 (랙 출처가 3D를 쓸 때)
- **할 일**
  1. 물량과 배치의 기준은 우리 Base(PLOT + 산출근거 + 사람 결정)이고, 3D는 높이와 구조물 확인용이다.
  2. 높이는 3D 값을 쓴다.
  3. PLOT 랙과 3D 랙이 30% 이상 겹치면 같은 랙으로 보고 형상은 3D를 쓴다.
  4. 위치 차이가 5 m 이하면 그림만 맞추고 물량은 Base대로 둔다.
  5. 3D에만 있는 구조물(오버브리지 · 서브 랙)은 물량 영향과 함께 보여 주고 사람이 쓸지 정한다.
  6. PLOT에만 있는 랙은 Base대로 두고 배관팀에 알린다.
- **예외**
  - 장비 위치가 5 m 넘게 다르면 어느 도면이 최신인지 먼저 확인한다
  - 3D에만 있는 구조물 때문에 케이블이 2% 넘게 늘면 쓰기 전에 다시 확인한다
- **판정** 장비 위치 차이 > 5 m → HOLD. 사용 중인 3D 구조물로 케이블 증가 > 2% → HOLD. 나머지 차이는 INFO (목록에 남김).
- **근거**
  - 사용자 결정 2026-11-27 (Base 먼저)
- **기준값** pos_tol_m = 5, detour_pct = 2, same_rack_pct = 30
- **상태** DRAFT

## 컴퓨터 관점 (번역본 · 회사 AI · 개발자)

_마스터의 번역본입니다. 마스터와 다르면 마스터가 맞습니다._

- **P00 이 프로토콜 읽는 법 · 고치는 법** _(확인 필요)_: 권위 순서: master(엔지니어 관점) > translations.computer / translations.maintenance. 각 번역본은 from_master(마스터 지문)와 state를 가진다. from_master ≠ 현재 마스터 지문이면 state = '다시 번역 필요'로 보고 그 번역본을 근거로 쓰지 않는다 (마스터 원문을 쓴다). state = '질문 있음'이면 questions를 엔지니어에게 돌려준다. 번역본 수정은 마스터 지문 갱신과 함께만. 숫자는 params만 참조, 문장 안 숫자 기준 금지. 검사: tests/check_protocol.py (다시 번역 필요 · 질문 있음 = FAIL, 확인 필요 = 참고).
- **P01 같은 입력이면 같은 물량** _(확인 필요)_: 출력 = f(입력 파일 SHA-256, 설정값, 사람 결정 기록). 같은 상태 ID(엑셀 '_지문' 시트)면 같은 물량. 결과 파일 직접 편집 금지, 변경은 입력·설정·결정 기록으로만. 검사: 같은 입력으로 다시 계산한 STRUCTURED_MODEL_DATA records 해시가 같아야 함 (06 REPRODUCIBILITY).
- **P02 값이 부딪힐 때 우선순위** _(확인 필요)_: 값 결정 순서: 사람 결정(plot_decisions.json · decisions.json · overrides.json) > 승인된 3D 반영(decision_log.json, approved) > PLOT 자동 인식 > 설정 기본값. 상위 값이 있으면 하위 값은 쓰지 않음. 3D 반영은 P03 관문을 거친 것만 '승인된 3D'.
- **P03 3D 반영은 제안 → 미리보기 → 승인** _(확인 필요)_: 3D 반영 = 제안(proposals/<시각>.json) → 미리보기(물량 전후, JB 변화, PLOT 마크업 회색=지금 빨강=제안, 부딪히는 사람 결정) → 항목별 승인 → 승인 항목만 설정 반영 + decision_log 기록 + 리비전 스냅샷. 미승인 = 변경 0.
- **P04 랙 차선 · 충돌 시 계장이 비킨다** _(확인 필요)_: 트레이 배치: 랙 폭 방향 계장 차선(설정 W01·W02)부터 채움. 다른 공종 객체와 겹치면 폭 방향 이동 → 안 되면 위로 한 단(W05)씩 최대 W06단 → 그래도 겹치면 HOLD(V08). 다른 공종 객체는 읽기만.
- **P05 랙 위 트레이 높이 · 자리** _(확인 필요)_: ladder_on_rack 트레이 EL = 같은 방향 랙의 케이블 단 EL(3D RK.cable 또는 구조물 높이). 한 랙의 트레이는 길이 방향으로 겹치는 구간마다 폭 방향 슬롯을 따로 배정, 슬롯 간격 0.1 m. 위반 시 V02·V06 HOLD.
- **P06 경사 경로 없음** _(확인 필요)_: 경로 마디마다 수평 변화와 높이 변화가 동시에 있으면 낮은 쪽 높이로 수평 → 수직 라이저로 나눔. 남으면 V04.
- **P07 JB 위치** _(확인 필요)_: JB 자리 후보 = 랙 기둥 바깥(설정 J13 거리) · 장비 가장자리(J14) · 3D 랙 기둥 옆. 랙 칸·장비 상자(3D 포함, J1A) 안은 제외. 위반 시 V07 HOLD.
- **P08 3D 점검 HOLD는 사람이 판단** _(확인 필요)_: 3D 사전 점검 V01~V09 결과: HOLD 항목은 자동 수정 금지, 3D_REVIEW_PRECHECK에 객체 ID로 기록, 회사 AI 리뷰 답(CONFIRMED / FALSE_ALARM / NEEDS_PERSON)도 제안일 뿐.
- **P09 출력 관리** _(확인 필요)_: output/LATEST(종류마다 하나, 덮어씀) · ISSUED/R*_날짜(읽기 전용) · HISTORY(시각 붙은 원본, 지우지 않음). 모든 엑셀 끝 '_지문' 시트: 지문 ID, 상태 ID, Rev, 입력 SHA-256, 설정·결정 해시.
